# Arcade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Multiple moving game objects, one new drone per contact, independent of Şile/free-flight preferences.
**Architecture:** Pure arcade state owns authored toy loops/contact/respawn. Goals delegates arcade ticks; a separate Three.js view owns toy meshes and disposal. Main wires menu, local-only result and gated respawn.
**Tech Stack:** Existing JS/Three.js/Node test/Vite; no new dependencies.
**Spec:** docs/superpowers/specs/2026-11-01-arcade-design.md

## Global Constraints
- Preserve existing worktree, SOURCE ONE settings, map preference and TX15 calibration.
- No automatic ARM, realistic target tracking, academic scores, ranked/ghost submissions.
- All arcade times follow paused simulation time.

## Review Focus
- Held throttle during transition must never arm new drone.
- Fast contact, wrong object ordering, overlapping candidates must complete exactly one.
- Crash/reset must preserve completed objects; full retry clears them.
- Reference propulsion must not suppress game objects.
- Map switching/retry must dispose view resources and preserve preferred Şile.
